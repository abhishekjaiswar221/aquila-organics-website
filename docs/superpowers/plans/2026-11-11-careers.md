# Careers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish job openings, accept applications with a CV, and give HR_MANAGER and SUPER_ADMIN an inbox, with no invented jobs and candidate data kept out of logs and the audit log.

**Architecture:** New tables (`JobOpening`, `JobApplication`, `ApplicationFile`) and a `src/features/careers/` module. The public submit reuses the shared steps in `src/features/enquiries/pipeline.ts`, generalised only where they are enquiry-specific (rate-limit key prefix, an activity sink, a file-kind allow-list); RFQ and contact behaviour must stay byte-for-byte the same. Admin pages follow the full-admin patterns (`requireAction`, `recordAudit`, optimistic concurrency).

**Tech Stack:** Next.js 16 App Router (cacheComponents), Prisma 7 + Postgres, Zod, Vitest (unit + integration), Playwright.

**Spec:** `docs/superpowers/specs/2026-11-11-careers-design.md`

## Global Constraints

- Branch `feat/careers`. One commit per task. **No `Co-Authored-By` or "Generated with" trailers in any commit** (standing user rule).
- Run npm/npx/vitest/playwright from PowerShell at `Set-Location "d:\Abhishek-Jaiswar\Projects\aquila-organics"` (Git Bash `/d/...` breaks vitest). Start Postgres with `npm run db:up` if it is down.
- Next.js 16: read `node_modules/next/dist/docs/` before using an unfamiliar API. Admin pages: `export const instant = false;`, no `use cache`. `"use server"` files export only async functions (put constants and types elsewhere).
- Every exported Server Action authorises first with `requireAction()` (outside try/catch), then validates untrusted input, and returns typed results with our own messages only.
- Candidate data (name, email, phone, message, CV filename) never goes into `AuditLog`, console logs, the acknowledgement email or any URL. Audit rows hold ids, enum values and counts only.
- No job, salary, benefit, headcount or culture claim is invented anywhere; page copy uses the `Block` content-status model and passes the banned-claims scan.
- CV files: PDF or DOCX only, one file, 10 MB (extension + magic-byte checks via `validateAttachment`); stored under an opaque `cv-<32 random bytes base64url>` key; the storage key never reaches a browser.
- Prisma: use `npx prisma migrate dev --create-only --name <n>`, then `npx prisma migrate deploy`, then `npx prisma generate` (dev DB `aquila`, test DB `aquila_test` is migrated by the test global setup).
- RFQ and contact flows are not allowed to change behaviour: their existing unit, integration and e2e tests must pass unmodified (except where a test pins "Careers unavailable").
- `npm run test:int` and `npm run test:e2e` share `aquila_test` and never run at the same time (a DB lock refuses the second).
- Working copies use CRLF: use the Edit/Write tools for multi-line changes, not shell string replacement.
- Run the whole unit, integration and e2e suites after tasks that change shared output.

## Review Focus

1. ADMINISTRATOR, SALES_MANAGER, CONTENT_EDITOR (and signed-out visitors) must get 403 / 401 / login redirect on every careers admin page, Server Action and the CV route; HR_MANAGER must get 403 on products, categories, enquiries, settings, users and audit.
2. A draft, closed or deleted opening must never be public: not on the list, not at its URL (real 404), not in the sitemap, not in JSON-LD, and not selectable in the apply form's `?job=` parameter.
3. A malformed upload (an executable renamed `.pdf`, a zero-byte file, a 10 MB + 1 file, a `.png`, two files, a missing file) must reject the submission with nothing stored; a failure after the object is stored must leave no object and no row.
4. Deleting an application must remove its rows and its stored CV, and must be refused for HR/SUPER_ADMIN only; a CV download must be audited before any byte is sent and must refuse cross-site requests.
5. A replayed submission (same `submissionId`), a honeypot hit, and a rate-limited IP must create nothing and (for the replay) return the same reference; the acknowledgement email must contain nothing the candidate typed.

## Deviations as built

Reported by the implementing agents, and the fixes made while running the end-to-end suite.

- `ADMIN_HOME_PATH` became `/admin`; the bare `/admin` page redirects each role to its own landing page (`adminHomePath`: HR manager to `/admin/applications`, others to `/admin/products`).
- `HR_MANAGER` was added to the users allow-list so a super admin can create HR users.
- `src/features/careers/paths.ts` was added (pure URL helpers shared by the proxy, sitemap, pages and form).
- `ConsentField` gained a `label` prop (the careers consent wording).
- Email addresses are lower-cased in careers (`applicationSchema`).
- A honeypot hit returns a success-looking reference and stores nothing.
- Replay, insert and reference-clash logic is local to `careers/submit.ts` rather than a shared generalisation.
- `readAndValidateAttachments` gained a `keyPrefix` option (`cv-` keys).
- `listJobFilterOptions` was added for the applications inbox's opening filter.
- The CV route also sends a `Content-Security-Policy: default-src 'none'; sandbox` header.
- Deleting an application is two-step in the UI (ask, then confirm).
- Setting an application to its current status writes no audit row.
- Unrejected attempts are not audited (only completed changes and the CV download write audit rows).

Fixes found by the end-to-end run (Task 6):

- The admin header's brand link pointed at `/admin/products`, a 403 for an HR manager; it now points at `/admin`.
- Deleting an application called `refresh()` before the form could navigate away, so the page re-rendered as "Not found" and the user stayed on it; `refresh()` was removed and the form's redirect to the list now runs.
- The admin "Not found" page linked to `/admin/enquiries` (403 for HR); it now links to `/admin` ("Back to the admin").
- Existing e2e specs were updated for the intended changes: the signed-out `/admin` redirect target, the Not-found link text, and `/careers` in the sitemap's exact set.
